# План: раздел «Проверка» — запись своей игры под GTP-трек и анализ темпа

Новый инструмент: пользователь загружает GTP/MusicXML, играет под минус, запись идёт с
микрофона или линейного входа; после стопа запись ложится отдельной дорожкой под нотами,
синхронно со скроллом; кнопка «Анализ темпа» подсвечивает красным места, где игра вышла
из темпа относительно выбранной дорожки файла.

Роут: `/record`, подпись в навигации и заголовок страницы — **Проверка**.

Статус: реализовано — `app/pages/record.vue`, `app/components/RecordTimeline.vue`,
`app/composables/useRecorder.ts`, `useWaveform.ts`, `useTempoAnalysis.ts`,
`public/recorder-worklet.js`, `scripts/check-record.ts` (в `make test`).

## 2. Чего сейчас не хватает в движке (минимальные добавления)

В `useTabSynth` нельзя извне прочитать события нот и сетку тактов/долей — а картинке нужны
именно они. Добавить два публичных read-only геттера, ничего не меняя в звуке:

```ts
// уже вычисляется внутри buildEvents/buildSegments — отдаём наружу
get timeline() {
  return {
    duration: duration.value,
    beats: beatTicks,            // [{ tick, ms }] по всем нотным дорожкам
    bars: barMarks,              // [{ ms, index, timeSignatureNumerator, isRepeated }]
    events: events,              // [{ track, note, start(ms), dur, velocity, drum }]
  }
}
```

и один необязательный аргумент старта, чтобы запись и партитура пошли с одного сэмпла:

```ts
async function play(fromMs = position.value, atContextTime?: number) { … }
```

`atContextTime` — момент `AudioContext.currentTime`, когда уже посчитан общий «ноль»;
существующие вызовы `synth.play()` не меняются (дефолт).

Дополнительно: `bars` (метки тактов для сетки) — они уже собираются в `buildSegments`
как `barStarts`, нужно сохранить ещё номер такта и размер.

## 3. Единая шкала времени

Синхронизация построена на одной оси «мс от начала партитуры»:

```
t=0 ───────────── countInMs ─────────────── duration партитуры (synth.duration)
   [ 4 клика отсчёта ] [ игра пациента ... ] [ хвост ]
                      ▲
                      └─ ноль дорожки нот; запись начинается раньше и обрезается/сдвигается
```

- `pxPerMs` — зум (по умолчанию ~0.08 px/мс, то есть ~8 px на 100 мс), кнопки ¼ / 2× / подгонка
  по ширине.
- `offsetMs` — сдвиг записи относительно нуля (компенсация задержки, раздел 5). На экране
  `x = (ms + offsetMs) * pxPerMs`.
- Обе панели (ноты и запись) живут в **одном** горизонтальном скролл-контейнере с общим
  `scrollLeft`, поэтому синхронность скролла получается бесплатно и не рассинхронизируется.
  Метки дорожек — `position: sticky; left: 0` внутри левой колонки.

## 4. Ноты (верхняя панель)

- **Одна полоса (строка) на дорожку, всегда.** Никакого piano-roll и переключателей вида: высота
  строки фиксированная (~44 px), дорожки идут стопкой сверху вниз, время — только вправо.
- Внутри полосы нота = горизонтальный отрезок `x = start*pxPerMs`, `width = max(dur*pxPerMs, 3px)`.
  Высота ноты внутри полосы кодирует её MIDI-номер, отображённый в диапазон min…max **этой**
  дорожки (аккорд = стопка отрезков), толщина 3 px, цвет — акцентный. Ударные — одинаковые
  маркеры по нижнему краю полосы, без высоты.
- Слева на каждой полосе: название дорожки (sticky), `👁` показать/скрыть (по умолчанию видны все
  дорожки с нотами) и `Mute` (через `synth.applyTrackSettings` — глушит **звук**, не картинку).
- Сетка: вертикальные линии на началах тактов, номера тактов сверху, доли — бледнее. Сетка и
  линейка тактов общие для всех полос и для волны записи.
- Отдельный рендер `AlphaTabApi` не нужен: полосы строятся из тех же событий, что уходят в звук,
  значит рассинхрона картинки и звука нет by design. Скролл — строго вправо (горизонтальный),
  вертикального скролла у самих полос нет.

## 5. Запись

### 5.1 Поток

1. Пользователь нажимает **«Тестирование»**.
2. Браузер спрашивает доступ к микрофону (один раз, `getUserMedia`).
3. Короткая проверка уровня (2–3 с шкала): «Тишина» / «Нормально» / «Слишком громко» (клиппинг) —
   подсказка надеть наушники и не ставить мониторинг.
4. Идёт **отсчёт: 4 клика** в темпе первого такта партитуры. Мы **уже пишем** с первого клика
   (чтобы не потерять первую ноту), клики помечаются как `countInMs`.
5. На «ноль» одновременно: `synth.play(0, at)` и игра пользователя. Запись продолжается.
6. Конец: пользователь нажимает **Стоп** или партитура доиграла до конца → запись закрывается,
   живая волна заменяется точной волной из захваченных сэмплов.
7. Готово → кнопки «Анализ темпа», «Экспорт WAV», «Прослушать (только запись / вместе с GTP)».

**Одна кнопка.** «Тестирование» и «Стоп» — это одна и та же кнопка: в покое она запускает
запись, во время записи показывает «Стоп». **Повторное нажатие в покое стирает предыдущую
запись**: буфер, волна, регионы анализа и плейхед обнуляются, панель записи очищается — новая
запись начинается с чистого листа, без накопления графиков.

**Запись видна в процессе.** Уже записанная часть рисуется в дорожке записи сразу, по мере
поступления сэмплов (волна растёт слева направо под плейхедом), а не после остановки.

Состояния: `idle → requesting → leveling → countIn → recording → ready` (переход `idle`
очищает предыдущее состояние).

### 5.2 Захват без «фона» и без наводок

```ts
navigator.mediaDevices.getUserMedia({
  audio: {
    echoCancellation: false,   // ключевое: эти три DSP-этапа «дышат» и гудят
    noiseSuppression: false,
    autoGainControl: false,
    channelCount: 1,
    sampleRate: 48000,
  },
})
```

Граф обработки (мониторинг НЕ подключается к `destination` — иначе акустическая завязка/вой):

```
MediaStreamSource → highpass(80 Гц, Q .7) → gain → AudioWorkletNode(recorder) → gain(0) → destination
                                           └→ AnalyserNode (уровень/клиппинг, только индикатор)
```

- Запись — **сырой PCM** через `AudioWorklet` (`public/recorder-worklet.js` копит блоки по 2048
  сэмплов и отдаёт их на главный поток), а не `MediaRecorder`: точное число сэмплов, никакого
  кодека и последующего `decodeAudioData`, одинаково работает в Chrome/Safari/Firefox.
- Ворклет подключён к `destination` через gain 0 — иначе граф не «тянется» и `process()` не
  вызывается; нулевой gain гарантирует, что в колонки ничего не уходит.
- Раз в кадр индикатор смотрит `AnalyserNode` (peak) и показывает клиппинг; при клиппинге в
  результате висит подсказка снизить громкость на устройстве.
- Сэмплы попадают в построчный буфер сразу и превращаются в пики для волны, поэтому запись видна
  в процессе; при остановке пики пересчитываются по полному буферу.
- Параметры захвата и клиппинг попадают в карточку записи: устройство (`label`), sample rate,
  длительность, пик, число сэмплов клиппинга.
- Ограничение: сырой PCM — 48 кГц × 4 байта ≈ 11.5 МБ в минуту; при записи длиннее ~15 минут
  показываем предупреждение о памяти.

### 5.3 Компенсация задержки

Задержка = выходная (`AudioContext.outputLatency` + `baseLatency`) + входная (буфер устройства,
`MediaStreamTrack.getSettings().latency` — если браузером отдаётся).

- Автоматически стартуем с `offsetMs = −(outputLatency*1000 + inputLatency*1000)` (запись
  сдвигается вправо, чтобы совпасть с нотами).
- Рядом слайдер **«Сдвиг записи»** ±300 мс с шагом 5 мс: при движении волна едет поверх сетки,
  пользователь совмещает первую ноту с первым тактом. Значения `auto` / `manual` показываются
  числом.
- Опционально (в плане как шаг 2): автокалибровка по клику отсчёта — запись идёт с включёнными
  кликами, ищем первый онсет в буфере и сравниваем с известным временем клика.

## 6. Нижняя панель — запись

- Волна по пикам: `peaks = min/max` на каждый пиксель (`bucket = 1/pxPerMs` мс), считается один
  раз в `Float32Array` и рисуется в `<canvas>` при изменении зума/размера.
- Внутри волны: серым — участок отсчёта (`0..countInMs`), он играется только если включён
  переключатель «с отсчётом».
- Плейхед общий с нотами, перетаскивается кликом по любой панели (seek).
- Прослушивание: `AudioBufferSourceNode` из `decodeAudioData`, старт с произвольного места.
  «Только запись» — источник прямо в `destination`. «Вместе с GTP» — источник и `synth.play()`
  стартуют на одном `AudioContext.currentTime` (`synth.play(from, at)`), так что совпадение
  сэмпл-в-сэмпл.
- Экспорт WAV (16 бит PCM) из `AudioBuffer` — чистая функция, тестируется в Node.

## 7. Анализ темпа

Кнопка **«Анализ темпа»** + выбор «с какой дорожкой сравнивать» (по умолчанию — дорожка с
наибольшим числом нот; можно несколько).

### 7.1 Ожидаемые онсеты

Из `synth.timeline.events`, отфильтрованных по выбранным дорожкам, берём уникальные `start`
(допуск кластеризации 30 мс: аккорд = один онсет, ударные тоже). Получаем
`expected = [{ ms, index, beat }]`. `beat` — номер доли/такта для отчёта.

### 7.2 Онсеты записи

Чистая функция `detectOnsets(samples, sampleRate, opts)`:

1. RMS-огибающая, hop 5 мс, окно 20 мс.
2. Адаптивный порог: `max(floor, median(последние 400 мс) * 2.5)`; онсет = фронт, где RMS
   вырос на ≥ 1.5× и достиг локального максимума, плюс минимальная пауза между онсетами
   (60 мс), чтобы не дробить одну атаку.
3. Дополнительно spectral-flux по 512-точечному FFT для инструментов с плавной атакой
   (скрипка, вокал) — включается, если RMS-детектор даёт < 50 % совпадений.

Алгоритм живёт без Vue-зависимостей, тестируется на синтетике (щелчки/синусы с известными
временами).

### 7.3 Сопоставление и регионы ошибок

1. Перевод онсетов в шкалу партитуры: `ms_score = ms_record + offsetMs`.
2. Жадное сопоставление по порядку: для каждого ожидаемого онсета берём ближайший ещё не
   использованный детектированный в окне `±(доля/2)`, иначе «пропуск».
3. `dt = detected − expected` (мс). Ошибка темпа в точке: `|dt| > threshold`
   (по умолчанию 120 мс, слайдер «Допуск: 60…250 мс»).
4. Регион = 2 и более подряд идущих ошибки (или одна, если `|dt| > 2×threshold`);
   границы — от первой до последней ошибочной ноты, `+20 %` ширины для читаемости.
5. Итоги: доля попаданий, средний `|dt|`, максимальный `|dt|`, и тренд — линейная регрессия
   `dt` по номеру доли: «торопитесь, −18 мс на такт» / «отстаёте, +12 мс на такт» / «темп ровный».

Регионы рисуются: красная полупрозрачная полоса на панели нот и на волне, подпись
«−140 мс, такт 5, доля 2». Клик по региону — seek в эту точку и прослушивание.

## 10. Как проверять без микрофона

- Юнит: `scripts/check-record.ts` (пики, WAV, онсеты, сопоставление, регионы) — единственный
  полностью детерминированный слой.
- Браузер: Chrome с `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` даёт
  синтетический вход; плюс отладочный хук `window.__recordDebug.feed(buffer)` — подсунуть
  заранее сгенерированный буфер и проверить панели и анализ без разрешений.
- Скриншоты через `ImageRenderer` не годятся (это веб): снимаем `Page.captureScreenshot` и
  сверяем `getBoundingClientRect()`/`scrollLeft` двух панелей численно.

## 11. Риски и решения

| Риск | Решение |
|---|---|
| `MediaRecorder` в Safari отдаёт `audio/mp4`, не `webm` | перебор поддерживаемых `mimeType`, дальше `decodeAudioData` — формат не важен |
| Микрофон требует secure context | страница на Pages уже https; локально `localhost` тоже считается secure |
| Большая запись (10 мин) в памяти | держим только `AudioBuffer` + пики; `MediaRecorder` chunks склеиваем один раз, сырые Blob освобождаем |
| Дрейф между GTP и записью на длинных вещах | оба идут от одного `AudioContext`; партитура планируется по `currentTime`, запись пишется настенным временем — расхождение меньше 1 мс на 10 мин, компенсируется `offsetMs` |
| Ошибки темпа ложно срабатывают на легато/паузах | порог 2+ подряд, окно ±½ доли, ручной допуск, отключение spectral-flux |
| Шумовая дорожка (фон) даёт ложные онсеты | адаптивный порог от медианы, минимальный интервал, highpass 80 Гц при захвате |

## 12. Вне скоупа этого этапа

- Сохранение записей между сессиями (IndexedDB), облако, шаринг.
- Определение неправильных **нот** (высота/аккорд) — только темп.
- Многодорожечная запись, наложение нескольких дублей.
- Автокалибровка задержки по клику (описана как шаг 2 после базовой версии).
